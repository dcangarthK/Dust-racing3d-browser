## S1 — Headless sim

- Verdict: GO-with-conditions
- Extraction approach recommended for Phase 2: null surface (MC_HEADLESS) because the null-surface path ran full races with no GL context and no offscreen fallback. Physics reads only CPU-side geometry: surface width, height and z come from the decoded image and the metadata, never from a texture. None of the 42 hacks fakes state that physics reads, so the kill check never fired. The coupling the hacks expose (the `Game` singleton, `Renderer::instance()` in factories, `Scene`-owned particle and sound singletons, `GraphicsFactory` text) maps to bounded refactors (see Phase 2 resolutions, rows 24-42). A full SimObject/RenderObject split would rewrite `MCObject`, whose pimpl owns both shape and view. Do it later, as a link-time split of MiniCore into core and renderer (rows 1-23).
- Links without OpenGL: no — via QtGui. `QtGui.framework` itself links `OpenGL.framework`, and the `Qt6::Gui` CMake target adds `-framework OpenGL` (plus AppKit and Metal) to the link line through `INTERFACE_LINK_LIBRARIES`. The harness's own objects reference 0 GL symbols (`nm -u`: no `gl*`, `CGL*`, `NSOpenGL*`, `glew*`), no GL context is created, and `QT_QPA_PLATFORM` is unset with no `QGuiApplication` constructed. Qt modules still required: Core, Xml, Gui. Gui is needed only for `QImage` decode and scaling in `MCSurfaceManager` and for `QColor`. `QPixmap`/`QPainter`/`QFont` symbols are still linked from `GraphicsFactory::generateMinimapMarker` and the non-headless branch, but never run. Condition: QtGui must go for a true no-OpenGL binary (replace `QImage` decode in the asset path).
- Laps completed: 3/3 (1 car: 5788 ticks, 92.6 s sim time, best lap 29.6 s, validator `ok`, 3 `lap` events); 12-car: ran. 3 laps for all 12 cars, 7721 ticks, 36 `lap` events, validator `ok`. No grid or collision crash.
- Repeatability: PASS 5788 ticks (1 car) and PASS 7721 ticks (12 cars), with the 12-car result identical across 6 further consecutive runs. Before the fix the 1-car run was already repeatable, but 12-car runs diverged as early as tick 315 (first differing hash line 316). All 6 unfixed runs gave different hashes and finished between tick 7715 and 7752. Cause: MiniCore keeps colliding objects and contacts in `std::set`/`std::map` keyed by `MCObject *`, so collision and contact processing order followed heap addresses, which change from run to run. Fix: a creation serial on `MCObject`, with the collision pairs, resolver pairs and contacts sorted by serial at the iteration sites (rows 39-42). Row 41 is more than a reorder: the resolver pass now tests a snapshot of the pairs that existed at the start of the pass. Upstream also re-tested pairs inserted during the pass, so per-pass pair counts and the resolver's early exit can differ from upstream (see row 41). Seed reaches the AI: seed 42 vs 43 differs from tick 68 (1 car), and no WARN for 12 cars.
- Hacks logged: 42 (see dependency-map.md: rows 1-23 from Task 10, rows 24-42 from this task); by category: GL 23, singleton 5, Qt 2, audio/render stubs 6 (audio 2, render 4); also telemetry accessors 2 and determinism 4. Of the 19 Task 11 rows, 11 change DustRacing2D source (2 accessors, 1 `game.hpp` member guard, 4 render/Qt guards, 4 determinism), 6 are spike-side stubs or CMake source additions, and 2 are harness-only.
- Units verified: velocity factor `m/s = velocity() × 0.05 × 1000 / tickMs` = ×3.125 at 16 ms. `MCPhysicsComponent::integrate` adds `velocity()` to the location once per step (mcphysicscomponent.cc:323), so velocity is world units per tick, not per second. Checked against the emitted feed: position-derived speed ÷ emitted |(vx, vy)| has median 1.0016 (p5 0.988, p95 1.003). Note that `speedKmh` is the game's own `speedInKmh()` (|v| × 3.6 × 2.75, tuned for display), which reads 0.87× the true speed from vx/vy (median). Heading convention: `Car::angle()` is degrees counter-clockwise from +x in the y-up world frame, emitted as radians in [0, 2π). It matches the velocity direction (median |Δ| 0.058 rad, p95 0.22 rad, which is tyre slip).
- Evidence: samples/s1-monza-1car.telemetry.ndjson (also samples/s1-monza-12car.telemetry.ndjson), run_twice output in evidence/s1-repeatability.txt

### Notes for later phases

- `pos` clamp (controller ruling): it fired. `Race::position()` is 0 until a car first reaches checkpoint 0 (about 1 s after lights out), so 20 snapshot entries per car were clamped from 0 to 1: 20 in the 1-car sample, 240 in the 12-car sample, and 63 in the 62.5 Hz tick feed. It never fired in a `result`.
- Off-by-one in tick labels (brief harness, kept as written): the snapshot labelled tick 0 is the state after the first 16 ms step, so `tMs` lags sim time by one tick. Consumers that treat tick 0 as the initial grid state should know this. Phase 2 should label the state after N steps as tick N.
- `progress` jumps from about 0.96 to 0 at the line on Monza (28 nodes). The lap ticks over when the car enters checkpoint 0's box, before the projection reaches node 0. This is fine for ordering. A gap or interval tower needs the continuous `(nodeIndex + fraction) / nodeCount` from the sim itself.
- `speedKmh` vs `vx`/`vy` disagree by about 12 % (above). Contract v0 does not say which is truth. Recommend deriving `speedKmh` from velocity in Phase 2, or documenting it as "game display speed".
- `MCGLScene::initialize()` was never needed: no code path in the race loop binds a shader program.
- The harness mirrors `Scene` in three places beyond the brief: track-object placement (mesh base-z offset and `Pit::pitStop` → `Race::pitStop`), a `ParticleFactory` instance, and silent per-car `CarSoundEffectManager`s. It does not build bridges (Monza has none) and does not run the start-light countdown: `Race::start()` is called at tick 0 and the AI drives from the first tick.
- Throughput (RelWithDebInfo, M-series laptop): 1 car, 3 laps (92.6 s sim) in about 2.3-3.6 s user; 12 cars, 3 laps (123.5 s sim) in about 7 s user, including about 1 s of asset and track loading. That is roughly 17-40× real time.
- The determinism rows (39-42) are unguarded and change collision order in the desktop build too. Row 41 also changes which pairs each resolver pass re-tests (a snapshot instead of the live map). The desktop build still compiles and ctest passes 5/5, but desktop collision behaviour has not been validated. Phase 2 should validate it before keeping row 41, and should replace the process-global serial with per-world stable IDs (row 39).
- Time used: well under 1 of the 3 agent-assisted days.
