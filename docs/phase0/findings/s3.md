## S3 — Render

- Verdict: GO
- Summary verdict: GO-with-conditions — see [../findings.md](../findings.md)
- Monza renders: yes; tiles 665 (35x19), route nodes 28 (route line sits on the asphalt tiles in evidence/s3-map.png, so the tile and node mappings agree)
- Frame time (60 s, 1024x768 CSS px, dpr 2 @ ~120 Hz): p50 8.3 ms, p95 9.8 ms (p99 10.2 ms, max 51.6 ms, 1 frame of 7971 over 20 ms). Refresh rate inferred from rAF cadence (119.8 Hz mean), not queried from the OS. This is vsync-paced rAF interval, not GPU cost, so it shows the 12-box scene has no trouble holding 120 Hz here, not how much headroom exists.
- Smoothness from 20 Hz feed: snapshots arrive 16/48/64 ms apart (every 3-4 ticks, ~20 Hz). Time-based interpolation (`sampleAt` against the wall clock) absorbs that jitter: replaying car 0 through `sampleAt` at 120 Hz gives a constant 0.358 m step per frame (min = max to 4 s.f.), so no stepping at snapshot boundaries; the chase and top views looked smooth by eye. The mock motion is constant-speed on a circle, so this does not test accelerations. Playback is clamped at the feed ends (feed is 74.7 s; the 60 s run stays inside it). From tick feed: not measured in S3. S5 rendered the real 12-car S1 feed live (real AI driving with braking and acceleration, not the mock circle): cars stayed on the route line, render frame time p50 8.3 ms / p95 10.0 to 10.3 ms (see [s5.md](s5.md)); interpolation smoothness under acceleration was not measured numerically.
- Coordinate mapping: Dust world (y-up, units) → scene x = x·0.05, z = −y·0.05; heading → rotation.y unchanged. Contract positions are metres, so `main.mjs` divides by METERS_PER_UNIT and then calls `worldToScene` (the brief's double conversion), which cancels to scene x = x_m, z = −y_m. I kept the brief's form and did not add `metresToScene`; if the tick-feed work wants it, it is a one-line addition with a test. The chase view confirms heading is right (cars drive forward, the follow car's lead car is ahead).
- Snapshot fields the renderer actually used: tMs, cars[].id, x, y, heading (speedKmh is interpolated by `sampleAt` but not rendered). Everything else in the snapshot (vx, vy, throttle, brake, steer, gear, lap, progress, pos, phase) was unused.
- apex-gp car reuse: lifted cleanly (nothing from apex-gp committed). `createCarModel(fullGrid()[0], { detail: 'low' })` from `apex-gp/src/car/chassis.js` + `livery.js` built and rendered in a standalone local page (11 meshes, 2.0 x 1.07 x 5.76 m, ~1.7 s one-off build, no console errors). Closure is 7 files, no engine or game state: car/{chassis,livery,materials,wheels}.js (7.8k lines), core/{assets,rng}.js, textures/procedural.js. Globals: needs a DOM (`document.createElement('canvas')` in wheels.js; `OffscreenCanvas` or canvas fallback in livery.js and procedural.js) for procedural textures. Gotchas: apex-gp declares three ^0.185.1 while the spike pins 0.176.0 (it resolved to 0.176 and worked; a real reuse should pin one version), model nose points to −z so it needs a heading offset, and the 1.7 s build plus 12 cars of per-car materials/textures was not measured. Not wired into `main.mjs`: importing a gitignored path from committed code would break for anyone without apex-gp, and the licence is unresolved. The spike keeps the box car.
- Evidence: evidence/s3-chase.png, evidence/s3-top.png, evidence/s3-frametime.txt (also evidence/s3-map.png, whole-track overview)

### Notes
- Vite serving: `resolve.alias` for `/levels`, `/images`, `/samples` did NOT work in dev mode (requests returned `index.html`, HTTP 200 text/html). The documented symlink fallback worked: `predev` script creates `public/{levels,images,samples}` symlinks; `spikes/s3-render/public/` is gitignored. `vite.config.mjs` therefore carries no aliases.
- Deviation from the brief: added a URL-only `&cam=map` overview camera (whole tile grid from 340 m up). The mock feed is a circle (centre 400,300 m, radius ~159 m) that is mostly off the 448 x 243 m Monza grid, so chase/top views alone cannot show the track. `c` still toggles chase/top.
- Mock feed vs Monza: the cars only overlap the track in the lower arc of the circle (roughly 15-22 s of each ~25 s lap); screenshots were taken at ~16 s for that reason. This proves playback, not alignment.
- The in-app browser pane stops firing rAF while it is hidden (0 samples over a 55 s hidden window), and the HUD shows "—" for p50/p95 until 61 samples exist. The frame-time run was taken with the pane visible.
- Screenshots were saved by converting the browser tool's JPEG to PNG with `sips` (800x600).
